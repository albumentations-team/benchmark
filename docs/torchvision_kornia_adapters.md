# TorchVision and Kornia adapters

The benchmark uses AlbumentationsX as the reference. TorchVision and Kornia run their own image operators. The adapters handle differences in input format, parameter units, sampling, and batch APIs. This inventory applies to the active RGB and grayscale catalogs with TorchVision 0.29.2, TorchCodec 0.17.0, and Kornia 0.9.1. Recipe numbers follow the order of the active catalogs. ## JPEG to CUDA batch

| Path | What the benchmark does and why | Code |
| --- | --- | --- |
| TorchVision CPU | Workers use `torchvision.io.decode_image` to get RGB bytes in a CHW `uint8` tensor. A v2 `Compose` runs the image stages once per sample, so every sample gets its own draws. Workers stack the results. CUDA converts the batch to FP16, divides by 255, and calls v2 `Normalize` in place. The byte batch keeps the host-to-device payload smaller. | [Reader](../src/augbench/adapters/sources.py#L33) · [Recipe](../src/augbench/implementations/torchvision_pipeline_impl.py#L24) |
| TorchVision GPU | Workers read the JPEGs from the shared EXIF-free cache and pass a list of compressed bytes to TorchCodec on CUDA. TorchVision runs the prefix through the first shape-forming stage per image in `uint8`, then stacks the equal-size results. An ordinary tail runs per image on FP16 data scaled to [0, 1] at entry. One v2 `Normalize` call finishes the batch. Per-image calls preserve independent draws for v2 transforms that share parameters within one call. | [Reader](../src/augbench/adapters/sources.py#L39) · [CUDA recipe](../src/augbench/implementations/torchvision_pipeline_impl.py#L42) · [Dataset preparation](benchmark_execution_contract.md#data-access) |
| TorchVision GPU decoder setup | The VM bootstrap locates the NVIDIA driver-matched `libnvcuvid.so.1`. If the image lacks the matching library, bootstrap stages it and adds its directory to the TorchVision GPU worker's loader path. This makes the L4 hardware JPEG backend available to nvJPEG. | [Bootstrap](../infra/gcp/bootstrap.sh#L41) · [Worker environment](../src/augbench/guest_worker.py#L115) |
| Kornia CPU | Kornia I/O with `kornia-rs` decodes RGB or grayscale as FP32 in [0, 1]. Workers temporarily add a batch axis to each image, run the declared stages, then remove it for collation. The collated host batch is cast to FP16 to halve transfer bytes. CUDA applies one `kornia.enhance.Normalize` call using the recipe's statistics. | [Reader](../src/augbench/adapters/sources.py#L43) · [CPU recipe](../src/augbench/implementations/kornia_pipeline_impl.py#L31) |
| Kornia GPU | The host runs the prefix through the first shape-forming stage in FP32, so samples stack even when source JPEG sizes differ. The host casts the stacked batch to FP16. The GPU runs the remaining stages on the batch and normalizes it once. The adapter sets `same_on_batch=False` on modules that expose that flag, so a batched call can draw independently where the native sampler supports it. ColorJitter needs separate handling for operation order. | [Stage split](../src/augbench/implementations/recipe_stages.py#L28) · [GPU recipe](../src/augbench/implementations/kornia_pipeline_impl.py#L101) · [Sampling flag](../src/augbench/implementations/kornia_common.py#L9) |
| Shared dispatch and output | The runtime binds the sample, host-batch, and device-batch calls and moves the device transform to CUDA on first use. The DataLoader preserves the seeded file order. The consumer transfers host tensors non-blockingly or passes the compressed list to TorchCodec. It validates and materializes a CUDA FP16 BCHW batch. `Normalize` and `ToTensor` remain in the recipe configs and are filtered from the Python image stages. The GPU normalizer reads `mean/std` from the recipe. | [Adapter runtime](../src/augbench/adapters/runtime.py#L63) · [Consumer](../src/augbench/execution/pipeline.py#L149) · [Recipe metadata](../src/augbench/implementations/recipe_stages.py#L13) |

### Kornia's FP32 GPU stages

The GPU tail normally takes FP16. For seven stages, `_Float32Transform` casts the input to FP32, runs the native operator, then casts back to FP16. This sets the arithmetic precision for those stages and keeps the same batch interface for the next stage and CUDA normalization. The allowlist is a benchmark choice. Its casts are part of the timed path. [Allowlist and casts](../src/augbench/implementations/kornia_pipeline_impl.py#L18)

On a local CPU check with four 224×224 tensors and matched seeds, running directly in FP16 versus through the FP32 wrapper gave mean absolute output differences of 2.91 for R09 Perspective, 1.22 for R47 ThinPlateSpline, and 0.78 for R72 ShiftScaleRotate in 0–255 units. R34 LinearIllumination and R35 CornerIllumination differed by at most 0.13 units per value. R23 Erasing and R69 CoarseDropout were bitwise equal on that input. These are CPU observations. The individual CUDA effects of the casts have yet to be measured.

## What the recipe adapters change

`v2.Lambda` and Kornia's `_TensorOperation` let the runner call a native function as a recipe stage. The tables name the native function and the work that happens around it.

### Geometry and placement

| Recipe | Adapter work and reason | Code |
| --- | --- | --- |
| R01 Resize, R03 RandomResizedCrop | Both adapters pass explicit output size and interpolation and disable antialiasing for these recipes. R01 uses a square size so the output is exactly 224×224. R03 passes the area and aspect ranges to the native sampler. Kornia uses `align_corners=False` and R03 uses its native slice-and-resize mode. These settings target half-pixel bilinear resize and avoid an extra downsampling filter. | [TorchVision](../src/augbench/implementations/torchvision_impl.py#L31) · [Kornia R01](../src/augbench/implementations/kornia_impl.py#L512) · [Kornia R03](../src/augbench/implementations/kornia_impl.py#L469) |
| R02 RandomCrop224, including its use as preparation | For short axes, TorchVision computes centered padding and calls native `pad` before native `RandomCrop`. Kornia supplies the same padding amounts through its `RandomCrop.compute_padding` hook. Each library pads and samples the crop itself. Centering puts one extra pixel on the bottom or right for an odd deficit and gives each operator a valid canvas. | [TorchVision](../src/augbench/implementations/torchvision_impl.py#L41) · [Kornia](../src/augbench/implementations/kornia_impl.py#L399) |
| R06 Pad | TorchVision maps the configured border width, fill, and mode to its native `Pad`. The separate RandomCrop224 stage forms the output shape. | [TorchVision](../src/augbench/implementations/torchvision_impl.py#L156) |
| R08 Affine, R72 ShiftScaleRotate | Both select native `RandomAffine`. The adapter turns symmetric X/Y shift limits in pixels into fractions of the 224-pixel canvas and passes rotation, scale, and shear as native ranges. The operator samples and applies its own affine map. R72 uses the same operator with shear left at identity. | [TorchVision](../src/augbench/implementations/torchvision_impl.py#L170) · [Kornia](../src/augbench/implementations/kornia_impl.py#L386) |
| R09 Perspective | TorchVision draws four inner source points from folded Gaussian offsets, rounds the points for the functional API, and passes source and destination lists to native `perspective`. Kornia uses the points from its native uniform sampler, then makes the inner quadrilateral the source. Both compute the destination extent from the longest opposing source edges and keep the output canvas size. This follows AX's mapping from an inner region to the output, which avoids the black frame produced by mapping the full input inward. The library computes and applies the warp. | [TorchVision](../src/augbench/implementations/torchvision_impl.py#L193) · [Point sampler](../src/augbench/implementations/geometry.py#L120) · [Kornia](../src/augbench/implementations/kornia_impl.py#L449) |
| R10 Elastic | Both use the library's elastic transform and configure its maximum calibrated amplitude. TorchVision scales the native sampled displacement by a uniform draw from 0.5 to 1.0. Kornia scales the native noise field by an independent multiplier per sample before the library smooths and applies it. Both add a strength draw while keeping their native deformation. | [TorchVision](../src/augbench/implementations/torchvision_impl.py#L209) · [Kornia](../src/augbench/implementations/kornia_impl.py#L411) · [Field calibration](rgb_elastic_calibration.md) |
| R23 Erasing, R69 CoarseDropout | R23 passes the configured area and aspect ranges to native `RandomErasing`. Kornia passes the fill as a float to avoid inferring an integer sampling dtype. R69 uses the same native eraser with both area endpoints set to `(32/224)²`, aspect ratio fixed to 1, and zero fill. The operator samples the position of the single 32×32 hole. | [TorchVision R23](../src/augbench/implementations/torchvision_impl.py#L295) · [TorchVision R69](../src/augbench/implementations/torchvision_impl.py#L151) · [Kornia R23](../src/augbench/implementations/kornia_impl.py#L428) · [Kornia R69](../src/augbench/implementations/kornia_impl.py#L102) |
| R45 OpticalDistortion | Kornia fixes the native `RandomFisheye` center at normalized (0, 0) and samples its radial exponent from 45 to 90. The setting reduces the visible distortion of Kornia's native map. The map still moves source coordinates outward and leaves a wider black border than AX on the calibration crops. | [Kornia](../src/augbench/implementations/kornia_impl.py#L437) · [Reference and observed effect](benchmark_faq.md#what-is-the-reference-for-opticaldistortion-r45) |
| R46 Shear | Both call native `RandomAffine` with zero rotation and the configured X shear range. Passing only that range keeps Y shear at zero and leaves shift and scale at identity. | [TorchVision](../src/augbench/implementations/torchvision_impl.py#L184) · [Kornia](../src/augbench/implementations/kornia_impl.py#L497) |
| R47 ThinPlateSpline | Kornia uses the native five anchors and uniform offset sampler. The adapter picks the uniform half-width to match AX's Gaussian per-axis standard deviation of about 11.2 px at 224×224. Kornia solves the spline and samples the pixels. | [Kornia](../src/augbench/implementations/kornia_impl.py#L501) |
| R50 LongestMaxSize, R51 SmallestMaxSize | TorchVision calculates the aspect-preserving integer dimensions from the original shape and the requested long or short side of 512, then passes both dimensions to one native bilinear resize. Kornia calls its native `LongestMaxSize` or `SmallestMaxSize`. The following crop is a separate stage. | [TorchVision](../src/augbench/implementations/torchvision_impl.py#L96) · [Kornia](../src/augbench/implementations/kornia_impl.py#L529) |
| R53 RandomRotate90 | TorchVision draws one integer from 0 through 3 and passes its angle in degrees to native `rotate`. Kornia calls native `RandomRotation90` with the same range. The library chooses how it executes the quarter turn. | [TorchVision](../src/augbench/implementations/torchvision_impl.py#L75) · [Kornia](../src/augbench/implementations/kornia_impl.py#L481) |
| R54 RandomJigsaw | Kornia runs native `RandomJigsaw` with `ensure_perm=False` so its sampler can return the identity permutation, which AX also permits. The 4×4 grid divides a 224×224 crop evenly. | [Kornia](../src/augbench/implementations/kornia_impl.py#L485) |
| R58 CenterCrop | TorchVision calls native `CenterCrop`. Kornia uses native slicing `CenterCrop` for inputs large enough. If an axis is short, its adapter calls the native `center_crop` function in nearest mode with zero padding. That form handles the out-of-image part of the centered window. | [TorchVision](../src/augbench/implementations/torchvision_impl.py#L83) · [Kornia](../src/augbench/implementations/kornia_impl.py#L55) |
| R59 Crop | TorchVision passes the fixed top, left, height, and width to native `crop`. Kornia converts the window to four inclusive corners for native `crop_by_indices`. The conversion selects the same rectangle after Resize256. | [TorchVision](../src/augbench/implementations/torchvision_impl.py#L87) · [Kornia](../src/augbench/implementations/kornia_impl.py#L68) |
| R60 CropAndPad | TorchVision reorders the four configured border values for native `Pad`. Negative values crop and positive values pad in the same native call. | [TorchVision](../src/augbench/implementations/torchvision_impl.py#L91) |
| R62 PadIfNeeded | TorchVision computes the missing width and height and calls native `pad` on the right and bottom only if needed. Kornia calls native `PadTo(crop_if_exceeds=False)`. This keeps the top-left origin and preserves any axis already at or above the minimum. | [TorchVision](../src/augbench/implementations/torchvision_impl.py#L105) · [Kornia](../src/augbench/implementations/kornia_impl.py#L81) |
| R67 RandomScale | Each adapter draws one scale per image, converts it to integer output height and width, then calls native bilinear `resize` with antialiasing disabled. The draw applies to both axes. The later crop handles the variable output dimensions. | [TorchVision](../src/augbench/implementations/torchvision_impl.py#L114) · [Kornia](../src/augbench/implementations/kornia_impl.py#L85) |
| R68 RandomSizedCrop | Both configure native `RandomResizedCrop` with both area endpoints set to `(160/224)²` and aspect ratio fixed to 1. The native sampler chooses the location of the 160×160 crop, which the operator resizes to 224×224. | [TorchVision](../src/augbench/implementations/torchvision_impl.py#L146) · [Kornia](../src/augbench/implementations/kornia_impl.py#L95) |

### Color, filtering, and codecs

| Recipe | Adapter work and reason | Code |
| --- | --- | --- |
| R11 ColorJitter, R49 ColorJiggle | Both use native `ColorJitter` with the recipe's respective parameter ranges. Kornia's generator produces one order of the four adjustments per call, even with `same_on_batch=False`. The Kornia wrapper sends one image at a time to the native operator and concatenates results so each image draws its own order. TorchVision already runs per image. | [TorchVision](../src/augbench/implementations/torchvision_impl.py#L232) · [Kornia wrapper](../src/augbench/implementations/kornia_impl.py#L34) · [Kornia builder](../src/augbench/implementations/kornia_impl.py#L123) |
| R13 Grayscale, R14 RGBShift | TorchVision passes the output channel count to native `Grayscale`. Kornia uses native `RandomGrayscale(p=1)` for the RGB output in R13. For R14, Kornia divides the allowed shift by 255 before passing it to native `RandomRGBShift`, which accepts normalized units. | [TorchVision R13](../src/augbench/implementations/torchvision_impl.py#L245) · [Kornia R13](../src/augbench/implementations/kornia_impl.py#L253) · [Kornia R14](../src/augbench/implementations/kornia_impl.py#L344) |
| R16 GaussianNoise | TorchVision uses native `GaussianNoise` with clipping. Kornia runs native `RandomGaussianNoise` and clamps the output to [0, 1]. | R18 Posterize | TorchVision draws the number of bits from 4 through 7 for each image, then calls native `posterize`. | R24 JpegCompression, TorchVision | CPU runs native v2 `JPEG` with quality 30–90. GPU draws a quality per image, then groups samples by quality because `encode_jpeg` accepts one quality per call. | R24 JpegCompression, Kornia | The adapter draws one nominal integer quality per image from 30 through 90, then interpolates between the calibrated pairs 30→24, 70→63, and 90→89. | R25 RandomGamma, R37 Hue | Gamma uses the configured exponent range divided by 100. | R26 PlankianJitter | Kornia passes a weighted list to native `RandomPlanckianJitter`. | R27 MedianBlur, R32 Blur | Kornia draws kernel size 3 or 5 independently for every image.
